Last week we flagged a dense cluster of papers all probing "recursive self-improvement" (agents that edit their own prompts, harnesses, or tools) within a single week. GUARD: Stabilizing Recursive Self-Improvement with Regret Guidance

ML/AI
arXiv:2611.23476 · submitted ~Nov 19-20, 2026

When an agent edits its own harness, prompts, or tools to improve itself, a net benchmark-score gain can hide the fact that it just broke something that used to work. GUARD's fix is to track "regret" — regressions on previously-solved tasks — as a signal kept separate from the raw count of newly-solved tasks, and to gate which self-generated edits actually get accepted based on that split view. It's a small methodological change, but it targets exactly the kind of silently-accumulating technical debt that aggregate scores in this line of work tend to paper over.

Safe Personal RSI: Evaluating and Repairing Personal Agent Updates

ML/AI
arXiv:2611.23651 · submitted ~Nov 20-21, 2026

Applies the same self-editing caution to a more personal setting: an assistant (the paper's running example is a personal health assistant) that wants to update its own instructions based on how interactions go. Proposed changes are checked against a bank of safety test cases before being accepted, and if nothing passes, the update is simply rejected and the assistant keeps running on its current, already-vetted instructions rather than drifting. Reject-by-default instead of accept-by-default is a conservative design choice, but it's one that's been missing from a lot of flashier self-improvement work.

QDA: Closed-Loop LLM Quantization Design with Agents

ML/AI
arXiv:2611.23388 · submitted ~Nov 20-21, 2026

Instead of hand-tuning one quantization recipe and applying it everywhere, QDA has an agent search over per-model quantization configurations, scoring each candidate by how far its reasoning traces diverge from the full-precision model on held-out prompts it never sees during the search. Treating quantization-recipe design as a closed loop an agent can run — rather than a one-off manual tuning pass done by a human once per model family — points toward quantization becoming another thing that gets automated per-model rather than applied generically.

The self-improving-agent wave: five more entries from earlier in the week

ML/AI
arXiv:2611.19230, 2611.18114, 2611.17790, 2611.18856, 2611.19823 · submitted Nov 15-18, 2026

Rounding out the picture, a batch of related papers landed in the few days just before this week's window and hadn't been covered yet: CompoundingKernel uses a self-improving agent loop to search for GPU kernels, starting from zero and ranking first on several public SOL-ExecBench leaderboards. Interpretable Weight-Space Programming has an LLM agent write model weights and features directly as code, skipping gradient training entirely, to produce transformers that are transparent by construction. AutoRL is a multi-agent system that watches a live reinforcement-learning run, diagnoses what's going wrong, and applies fixes mid-training. Self-Improvement Memory stores the rationale and observed outcomes of past harness edits so future optimization runs don't have to rediscover them, and EfficientSkill learns agent skills for accuracy first, then prunes them down for length, cutting token usage without giving back the accuracy gains. Together with the three papers above, that's eight self-improvement-flavored papers in about ten days — a strong signal of where a meaningful slice of the field's attention currently sits, even if no single one of them settles the underlying question.

Migrating our Messages API to Rust

Lab
Anthropic, Engineering · Nov 25, 2026

A detailed account of rewriting the Messages API (whose traffic grew roughly 1,800x between early 2024 and this fall) from Python to Rust for lower CPU use, without downtime or a feature freeze — and without a test suite complete enough to prove correctness on its own. Their fix was to treat the live production system itself as the oracle: shadow real traffic against both implementations, replay a captured model output rather than re-running it (since Claude's outputs are nondeterministic), and diff privacy-preserving "fingerprints" of each pipeline step instead of logging actual request text. The result was a roughly 70% cut in CPU per request and over 80% less memory, with input-match rate against shadowed production traffic rising from about 24% to 99.6% as the approach matured. The more interesting part is where human effort ended up: not writing the Rust code, but designing a verification signal precise enough for agents to act on, and reviewing fixes at the boundary between an inner sandbox-testing loop and an outer production-shadowing loop.

Working with AI

Lab
Anthropic, Economics · Nov 23, 2026

Based on 66 interviews across 58 companies (all Anthropic customers, so take the sampling with appropriate salt), this report on enterprise AI adoption finds that the value companies report is mostly about doing more — accelerating existing work or enabling new products — rather than cutting costs, and that few report AI-driven layoffs even as many report hiring less and cutting offshore contractors. Its more interesting finding is structural: top-down, centrally-mandated automation tends to be brittle and provoke resistance, while purely bottom-up power-user experimentation stays siloed and adds maintenance burden; the approaches that actually capture value tend to broaden roles and redeploy staff toward judgment and interpersonal work AI can't yet do, backed by shared data infrastructure non-technical staff can use. The findings are explicitly framed as qualitative and exploratory rather than causal.

Pre-Training Without Learning Rate Decay

Blog
Sebastian Raschka · Nov 17, 2026

A short, workmanlike comparison of three LLM pretraining learning-rate schedules — cosine decay, warmup-stable-decay (WSD), and a constant learning rate combined with checkpoint averaging — looking at which actually yields a better final model for a given compute budget.
